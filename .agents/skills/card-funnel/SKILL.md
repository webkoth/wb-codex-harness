# Воронка карточек и черновики правок

## 1. Диагностика

1. Желательно, чтобы был свежий `$profit`: тогда потери считаются в **прибыли**, а не в выручке.
   Если отчёта нет, скажи об этом и продолжай. Потери будут в выручке, это подписано.
2. `npx tsx scripts/funnel.ts [--from … --to …] [--top 5]`. По умолчанию — 28 дней до вчера.
3. Покажи человеку:
   - медиану магазина по этапам (это база сравнения: отраслевых норм по категориям в открытых данных нет);
   - очередь правок: карточка, слабый этап, потеря в ₽;
   - «Не разгонять — сначала экономика»: карточки с прибылью на выкуп ≤ 0. Трафик в них увеличивает убыток.

Что значит слабый этап:
- **карточка → корзина**: фото, видео, рич-контент, цена на витрине, отзывы и рейтинг, размерная сетка;
- **корзина → заказ**: цена и её изменения, срок доставки (остатки по регионам, FBS против FBO);
- **заказ → выкуп**: соответствие фото и описания реальному товару, качество, размер.

## 2. Черновики (для каждой карточки из очереди)

Контекст уже собран в `drafts/<nmID>/context.json`: карточка (название, описание, характеристики, фото),
воронка против медианы, реклама, поисковые запросы (если доступны).

Напиши `drafts/<nmID>/draft.md` по шаблону:

```
# <артикул> · <nmID> · слабый этап: <этап> · потеря <₽>
## Диагноз — 2–3 предложения на цифрах из context.json
## Название — БЫЛО / СТАЛО (≤ 60 символов) / почему
## Описание — СТАЛО целиком / какие запросы вписаны
## Характеристики — что заполнить или исправить (id, название, значение)
## Фото — что поменять на главном и в галерее (для человека: сами фото мы не грузим)
## Как проверить — метрика, срок (≥ 14 дней), одна правка за раз
```

Правила черновика (подробно: `docs/card-rules.md`):
- **Название**: до 60 символов, формула «предмет + ключевые характеристики». Без повторов слов,
  без «№», «/», чужих брендов. Без «хит», «лучший», «скидка», «new/sale/hit»: за них с осени 2025 понижают в выдаче.
- **Описание**: связный текст, 5–10 ключевых запросов из `searchTexts`, начиная с самых частотных,
  где позиция слабая или переходов мало относительно конкурентов (`openCardPercentile` низкий).
  Лимит по предмету (обычно 2000 знаков, диапазон 1000–5000, точный смотреть в кабинете). Иностранные слова — с русским переводом (закон с 01.03.2026).
- **Характеристики** заполнять полностью: по ним работают фильтры.
- **Не выдумывай свойства товара.** Материал, размеры, комплектация, совместимость берутся только из карточки и характеристик.
  Нет данных — вопрос человеку в черновике.
- Если поисковые запросы недоступны (ошибка 403 в context.json), подбери запросы из названия предмета
  и характеристик и прямо напиши, что частоты не проверены.

## 3. Применение (только после согласования)

Черновики в кабинет **не пишутся** автоматически. Когда человек согласовал конкретный черновик:
1. `wb_update_card` без `confirm`: показать превью БЫЛО → СТАЛО.
2. После «да»: `wb_update_card` с `confirm=true`. Проверить блок ошибок в ответе.
3. Записать в конец `draft.md` дату применения и id записи журнала, чтобы через 14 дней сравнить воронку.

Фото, видео и теги через API карточки не меняются, их правит человек в кабинете.
